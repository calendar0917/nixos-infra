NixOS 26.05 双系统安装：唯一现场入口（Arch 主力机 LENOVO 21LG）
适用：给现有 Arch/Btrfs 机器新增 NixOS；Arch 的 @、@home、@log、@pkg 必须保留。
禁止 Calamares 自动分区，禁止安装 #nixos（那是小主机），禁止把 mini hardware 复制给 main。
现场只执行本目录的 START.sh；详细背景、排障和回退见 docs/ARCH_DUAL_BOOT.md。
【0. 先认机器，不看 hostname】
  main = LENOVO 21LG / ThinkBook 16 G6+ AHP / UMIS 953.9G NVMe
  mini = KOLOE ITX-FP5 / KingFast 238.5G（只作备份校验，不是安装目标）
  ISO 的 hostname 永远是 nixos；flake show 只出现 nixos 是正常的。

【1. Arch 上准备（小主机可达时）】
  sudo ./START.sh --record-backup
  # 只把 /var/tmp/esp-backup-record.txt 复制到 Ventoy/nixos-install/
  # 不要把 tar.gz、secrets、私钥或节点配置放到 Ventoy。
  确认 Ventoy/nixos-install/ 下有 START.sh、install-preflight.sh、repo/、cache/、
  esp-backup-record.txt；更新 bundle 时不要带入 .git/、result/、secrets/ 或任何
  hosts/main/hardware-configuration.nix（该文件必须由 ISO 现场生成）。

【2. 启动 ISO，进入 root shell，只读挂载 Ventoy】
  sudo -i
  VNT=$(findmnt -n -o TARGET -L Ventoy | head -1 || true)
  [ -n "$VNT" ] || { mkdir -p /run/ventoy; mount -o ro /dev/disk/by-label/Ventoy /run/ventoy; VNT=/run/ventoy; }
  bash "$VNT/nixos-install/START.sh"
  # START.sh 会自己再 bind 成只读视图；不要手动 remount rw，也不要把文件管理器里的
  # Ventoy 当成可写目标。
脚本会自动 re-exec 为 root；不要用 sudo 再包一层。菜单顺序：1 → 2 → 3 → 4。

【3. 菜单含义】
  [1] A 准备：发现 Ventoy 只读视图，复制 repo，cache 复制到可写临时目录再导入；
      不会 remount Ventoy rw，不会删除旧 cache，不需要 mini 在线。
  [2] B 网络：优先 ISO Wi-Fi / 手机 USB 共享；可选从 Arch @home 只读挂载启动本地
      Mihomo（私有临时副本、仅 127.0.0.1、无 TUN/DNS/防火墙改动）。mini 只是备用。
  [3] C 只读检查：UEFI、DMI 21LG、唯一 UMIS 盘、Btrfs/ESP UUID、Arch 子卷和默认
      子卷 5、ESP 上 Arch UKI/厂商文件、BootOrder、install-preflight；并用 Ventoy 上
      的 esp-backup-record.txt 逐文件比对当前 ESP。记录必须由 --record-backup 生成，
      且要人工确认 Restic 密码有离线副本；不通过就 STOP。
  [4] D 安装向导：D2 创建 @nixos* → D3 挂载 → D4 现场 hardware → D5 持久化/构建 →
      D6 验证 → D7 nixos-install → D8 密码 → D9 UKI/BootOrder → D10 卸载。
      每一步写盘前单独输入短语；没有 --yes/--force，没有无人值守模式。

【4. 写盘确认短语（区分大小写）】
  CREATE-SUBVOLS、MOUNT-TARGET、GENERATE-HARDWARE、PERSIST-FLAKE、BUILD-MAIN、
  INSTALL-NIXOS、SET-PASSWORD、INSTALL-MAIN；重复现场还会要求 CONTINUE-PARTIAL、
  REPLACE-TARGET-CONFIG；ISO 版本不一致时要求 STATE-VERSION-OK。
  看到 STOP 立即停止当前阶段；不要重启、不要删除子卷/快照、不要改默认子卷。

【5. 备份记录 STOP 的补救】
  若 C 报“ESP 文件与备份记录不一致”，说明备份后 Arch 内核/UKI 变过。回 Arch，
  在小主机可达时重跑 sudo ./START.sh --record-backup，再复制新的文本记录到 Ventoy。
  不要跳过检查、不要用旧记录、不要把 Ventoy 改成可写、不要伪造记录。

【6. 禁止事项】
  不 mkfs、不分区、不改 ESP/NVRAM、不 btrfs subvolume delete、不 set-default、
  不删 Snapper 快照、不覆盖共享 ESP、不安装 #nixos、不把 secrets/私钥/订阅写入
  Ventoy、Git、日志或 /mnt/etc/nixos。脚本不会自动重启。

【7. 重启后】
  默认启动项仍是 Arch；在 systemd-boot 手动选 NixOS 做首次验收，再回 Arch 确认
  原系统正常。阶段 E 的检查见 docs/ARCH_DUAL_BOOT.md。
  随时可用：bash START.sh --status（只读）、--cleanup（停 Mihomo/清理）、--help。
